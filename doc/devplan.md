# stable-gimpfusion3 开发计划

## 目标与方案

以本仓库的 **stable-gimpfusion3** 为基础继续开发，通过 Forge HTTP API 完成文生图、图生图和局部重绘。目标工作流为：

> 在 GIMP 中画图或修图 → 选择预设 → 确认来源图层与蒙版 → 点击生成或按快捷键 → 在结果图层组中挑选候选 → 继续编辑。

| 项目 | 确定方案 |
| --- | --- |
| 开发范围 | 本仓库的 Python 插件、GIMP 公开的 libgimp/libgimpui API |
| 运行环境 | 本机已安装的 GIMP 3.2 及其 Python 环境、本机 Forge 服务 |
| 操作界面 | 可调整宽度和高度的独立、非模态、常驻 GTK 窗口 |
| 侧栏效果 | 使用 Windows 自带分屏功能，将插件窗口与 GIMP 窗口并排贴靠 |
| 参数复用 | 命名预设保存提示词、生成参数、模型和 LoRA 配置 |
| 输入展示 | 显示目标图像、来源图层名称与缩略图，以及实际使用的蒙版来源 |
| 生成触发 | 窗口中的生成按钮，以及 GIMP 菜单命令绑定的快捷键 |
| 结果挑选 | 每批候选放入一个图层组，默认显示第一张候选，逐层切换比较 |

具体执行清单见 [TODO.md](../TODO.md)。两份文档使用相同的 S1–S8 编号：本文件说明实现步骤和完成条件，TODO.md 记录执行进度。

## S1 确认本机环境与现有流程

1. 在 GIMP 的 Python 环境中确认 `sys.version`、`sys.executable`，以及 PyGObject、GTK、Gimp/GimpUi、`requests` 的实际版本和导入结果。根据该环境确定后续语法和依赖要求。
2. 通过现有 ApiClient 连接目标 Forge，确认 `/sdapi/v1/txt2img`、`/sdapi/v1/img2img`、模型列表和 ControlNet 接口。通过该服务的 `/docs` 确认 LoRA 列表、刷新接口及返回字段。
3. 各执行一次文生图、图生图、选区局部重绘和图层蒙版局部重绘，记录实际输入、输出尺寸、插入位置和批量结果行为。
4. 梳理公共提示词与本次提示词的合成顺序，以及各模式使用宽高、选区边界、图层偏移和蒙版的规则，作为 S2–S5 共用的参数约定。
5. 在本机 GIMP 3.2 中确认常驻过程、临时 PDB 过程与 GTK 主循环的配合方式，为 S6 确定实现入口。
6. 排查现有界面中用途描述含糊的参数和帮助文本，从 `sg_proc_arguments.py` 中 `cn_skip_annotator_layers` 的说明入手。沿参数定义、API 请求与响应、结果图层处理的调用链调研，并通过本机 Forge 与 GIMP 操作明确对应功能的用途、开关效果和适用模式，形成 S8 修订文案的依据。

**完成条件：** 本机插件能够连接 Forge 并完成上述生成流程；Python 依赖、模式参数规则和常驻窗口所需接口已经明确；含糊界面说明对应功能的用途已经查明，文案修订依据清晰。

## S2 增加完整命名预设

**主要位置：** MyShelf、公共生成界面、参数定义和三种生成模式。

1. 在 `stable_gimpfusion.json` 中增加 `presets` 和 `last_preset`。`presets` 以名称为键，每个值保存一套完整生成配置；现有连接设置和命名预设分别管理。
2. 确定一套预设字段，并统一界面、存储和请求构建之间的对应关系：

   | 字段组 | 保存内容 |
   | --- | --- |
   | 模式与提示词 | txt2img/img2img/inpaint 模式、正向和负向提示词 |
   | 通用生成参数 | seed、batch_size、steps、cfg_scale、width、height、采样器、restore_faces、tiling |
   | 模式参数 | denoising_strength、resize_mode、mask_blur、inpainting_fill、inpaint_full_res、invert_mask、insert_mode 等现有模式参数 |
   | 模型 | `sd_model_checkpoint` 对应的模型标识 |
   | LoRA | 模型名称、提示词标签使用的标识、权重、启用状态 |
   | ControlNet | 两组开关、处理器、模型、权重等配置，以及辅助图层显示选项 |

3. 模型和采样器保存名称等稳定标识。来源图像、来源图层、ControlNet 输入图层和像素数据属于当前文档的运行上下文，预设负责保存可复用参数。
4. 在现有生成对话框顶部加入预设列表，以及“载入”“保存”“另存为”“删除”操作。载入时恢复对应模式及其参数；保存时写入当前完整配置。
5. 按 S1 的约定在请求构建处合成公共提示词、本次提示词和模式参数，并在界面显示实际生成尺寸。seed 的约定统一为 `-1` 表示随机，非负整数表示指定种子。
6. 预设应用模型设置后，再提交本次生成请求；ControlNet 输入图层由当前图像中的选择提供。

**完成条件：** 创建两套含不同提示词和生成参数的预设，重启 GIMP 后可分别载入并生成；保存、另存为和删除结果正确；载入值、界面值与实际请求值一致。

## S3 显示生成来源图层与蒙版

**主要位置：** img2img、inpainting、公共生成界面和图层转换函数。

1. 在图生图和局部重绘界面增加“输入来源”区域，显示目标图像名称、来源图层名称和缩略图。默认来源沿用当前选中图层列表的第一层。
2. 将当前使用的蒙版显示为“当前选区”或“来源图层蒙版”。局部重绘沿用当前选区优先、随后使用来源图层蒙版的取值顺序。
3. 在打开界面、窗口重新获得焦点和发起生成时刷新来源信息。发起生成时，使用同一次读取到的图像、图层和蒙版构建输入。
4. 图生图入口要求有效来源图层；局部重绘入口要求来源图层及可用蒙版。界面根据当前输入状态设置生成按钮，并显示需要补齐的输入项。
5. 文生图界面显示结果接收图像和选区范围；三种模式各自展示参与本次生成的输入。

**完成条件：** 在两个图层间切换并修改内容后，界面展示与实际发送的来源一致；选区和图层蒙版两种局部重绘流程使用正确的蒙版。

## S4 增加 LoRA 选择器

**主要位置：** ApiClient、公共生成界面、请求参数构建和预设字段。

1. 按 S1 确认的目标 Forge 接口，通过 ApiClient 获取 LoRA 列表。刷新操作先请求 `POST /sdapi/v1/refresh-loras`，再请求 `GET /sdapi/v1/loras` 更新列表。
2. 增加 LoRA 搜索、添加、启用、移除和权重编辑操作；模型显示名称与实际用于提示词的标识分别保存。
3. 在构建请求时，将启用项转换为 `<lora:标识:权重>`，与正向提示词合成一次最终请求文本。选择器配置独立保存，提示词编辑框保存用户输入的文本。
4. 明确同名 LoRA 的合成规则：以模型标识合并手写标签与选择器条目，启用的选择器条目提供最终权重。界面显示合成后的标签。
5. 将选择器状态接入 S2 的预设保存和载入流程。

**完成条件：** 可从 Forge 刷新并选择多个 LoRA，权重与最终请求一致；手写标签和选择器中的同名条目按约定合成；重载预设后恢复 LoRA 配置并完成生成。

接口设计参考 [WebUI 的 LoRA API 实现](https://github.com/AUTOMATIC1111/stable-diffusion-webui/blob/master/extensions-builtin/Lora/scripts/lora_script.py)，开发以 S1 确认的本机 Forge 接口为准。

<a id="s5"></a>

## S5 将每批结果整理为图层组

**主要位置：** ResponseLayers、LayerData 和三种模式的结果插入流程。

1. 每次生成创建一个 `AI Results` 图层组，以模式和批次序号区分批次。每张候选作为子图层插入，并在图层名中显示 seed。
2. 按 Forge 返回顺序排列候选，默认显示第一张，其余候选通过 GIMP 图层面板切换可见性。选中首张候选，供下一轮编辑和生成使用。
3. 保持候选图像、seed 和 infotext 一一对应；按 S1 调研明确的 `cn_skip_annotator_layers` 规则处理 ControlNet 辅助图层，并使用明确的辅助图层名称。
4. 将尺寸适配、偏移和选区蒙版处理应用到组内候选，并沿用 S1 确定的模式规则。
5. 继续在候选图层的 `gimpfusion` Parasite 中保存 `info` 和 `seed`，补充本次实际提交的生成参数、模式、模型和 LoRA 配置。
6. 将一批结果的分组、插入和属性设置合并为一次 GIMP 撤销操作。

**完成条件：** 一次生成四张候选，图层组内顺序、seed、默认可见性和插入位置正确；可逐张比较并继续编辑；撤销可移除本批结果；XCF 重新打开后保留生成信息。

## S6 实现可调整宽高的常驻窗口

**前置：** S2–S5 的参数、输入和结果处理已经完成。

**主要位置：** 插件入口、公共生成流程，以及新增的 `sg_plugins/panel.py` 窗口模块。

1. 增加“打开生成面板”菜单入口。以 `Gimp.PDBProcType.PERSISTENT` 过程承载窗口，注册临时 PDB 过程，调用 `persistent_ready()` 通知 GIMP 就绪，并通过 `persistent_enable()` 在 GTK 主循环中接收后续调用。
2. 将已完成的预设、提示词、来源预览、LoRA、模式参数和生成操作组织到一个非模态 GTK 窗口中。三种模式共用已有的参数构建和结果处理代码。
3. 支持拖动窗口边缘分别调整宽度和高度。使用纵向布局、滚动区域和可折叠参数区，让提示词与生成操作在窄窗口中保持可用。
4. 使用可参与 Windows 分屏的普通顶层窗口样式。用户通过系统自带分屏功能将 GIMP 放在一侧、插件窗口放在另一侧，并调整两者占用比例。
5. 面板明确显示当前绑定的目标图像。菜单或快捷键调用时接收 GIMP 传入的图像；窗口中提供目标图像选择，切换后刷新来源图层与蒙版。生成按钮作用于面板显示的目标图像。
6. 点击生成时，在主线程取得输入图像、图层、蒙版、选区和参数快照。工作线程通过 ApiClient 完成 HTTP 通信；GTK 状态更新、GIMP 图像读取和结果插入统一在主线程执行。
7. 一次执行一个生成任务，界面显示进度。任务期间生成入口呈现忙碌状态；用户可继续在 GIMP 中绘画，返回结果使用任务开始时确定的输入和目标图像。结果插入时集中执行 S5 的撤销操作。
8. 在结果插入入口处理目标图像已经关闭的情况，并显示该任务的结束状态。窗口关闭时保存当前参数和窗口宽高，释放临时过程并结束常驻进程；再次打开时恢复保存的状态。
9. 通过常驻进程注册的临时 PDB 过程接收打开、切换目标图像和生成操作，重复打开入口时呈现现有窗口。

**完成条件：** 窗口可调整宽高并参与 Windows 分屏；生成完成后持续显示；连续生成、切换图像和使用 GIMP 画笔顺畅；重复打开入口呈现同一面板；关闭后可重新打开并恢复状态。

常驻过程的就绪通知见 [persistent_ready()](https://developer.gimp.org/api/3.0/libgimp/method.Procedure.persistent_ready.html)，GTK 主循环中的消息处理见 [persistent_enable()](https://developer.gimp.org/api/3.0/libgimp/method.PlugIn.persistent_enable.html)，过程间调用见 [add_temp_procedure()](https://developer.gimp.org/api/3.0/libgimp/method.PlugIn.add_temp_procedure.html)。

## S7 接入按当前参数生成的快捷键

**前置：** S6 的常驻进程与临时 PDB 过程可用。

1. 注册具有固定名称和菜单入口的 `stable-gimpfusion-generate-current` 命令。它接收 GIMP 当前图像，将生成操作交给常驻面板，使用面板中的最新模式和参数。
2. 首次调用时启动面板并载入上次参数，待面板就绪后执行生成；后续调用直接交给现有面板。生成过程使用 S6 的任务与忙碌状态。
3. 将现有文生图、图生图和局部重绘菜单入口接入同一面板：切换到对应模式，并更新目标图像。
4. 在 GIMP 的“编辑 → 键盘快捷键”中绑定命令。建议将 `Ctrl+Alt+G` 绑定为按当前参数生成，具体按键由用户在 GIMP 中设置。
5. 在画布获得焦点时，用快捷键完成“读取当前图像及来源 → 使用面板参数 → 生成 → 插入候选图层组”。按钮与快捷键共用同一生成流程。

**完成条件：** 在 GIMP 画布上画几笔后，按快捷键即可使用当前图像、来源图层和面板参数生成；面板首次启动与已打开时均可触发；三种模式的菜单入口切换正确。

快捷键绑定方式见 [GIMP 菜单命令快捷键说明](https://docs.gimp.org/3.0/en/gimp-concepts-shortcuts.html)。
